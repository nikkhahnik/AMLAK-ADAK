# دسترسی چندمدیریری املاک آداک (نسخه توسعه)
این تغییرات هنوز در سایت زنده فعال نیستند. قبل از ادغام، راه‌اندازی و آزمون امنیتی لازم است.

## معماری
- مدیریت کاربران در `/admin/access.html`، فقط برای مالک فعال.
- بارگذاری تصویر همراه با امکان لغو در `/admin/upload.html`.
- `sql/adak-rbac.sql` سیاست‌های دسترسی را در Supabase اجرا می‌کند.
- `site-blocks.js` متنِ باکس‌های منتشرشده را از پایگاه داده می‌خواند؛ در صورت عدم اتصال، محتوای HTML اصلی دیده می‌شود.
- مدیریت کامل کد، قالب و فایل‌های مخزن هنوز تحت کنترل مجوزهای GitHub/Pages CMS است، نه نقش‌های این پنل.

## پیش‌نیاز
۱. یک پروژه Supabase اختصاصی آداک ایجاد و با حساب مالک تنظیم شود. به پروژه‌های سایر کسب‌وکارها وصل نکنید.
۲. ابتدا `db-schema.sql` روی دیتابیس تازه اجرا شود، سپس `sql/adak-rbac.sql`.
۳. کاربر مالک در Authentication ساخته و از مسیر قابل اعتماد SQL به عنوان `is_owner=true` فعال شود.
۴. فقط آدرس پروژه و کلید عمومی publishable در `backend-config.js` وارد شود؛ هیچ کلید secret/service_role در مخزن نباشد.
۵. اتصال GitHub و Pages CMS برای کارمندان محدود باید حذف یا به حساب/سرویس دارای سطح‌بندی مجوز منتقل شود. وگرنه کاربران با دسترسی مستقیم به GitHub می‌توانند از کنترل‌های UI عبور کنند.
۶. پیش از انتشار باید سیاست‌های RLS با حساب‌های تست (مالک، آپلودر، ویراستار، غیرفعال و ناشناس) و نیز بارگذاری لغوشده/موفق بررسی شوند.

## دامنه مجوزها
- `listings.view/create/edit/publish/delete`
- `media.view/upload/edit/delete`
- `private.view/edit`
- `pages.view/edit/publish`
- `layout.edit`, `theme.edit`, `settings.edit`
- `users.view/manage`

توجه: theme.edit، settings.edit، users.view و users.manage در حال حاضر بخش‌های رزروشده برای تکمیل سرویس تنظیمات/مدیریت‌اند و نباید به معنای عملکرد کامل آنها تعبیر شوند. مدیریت کاربران فعلاً تنها برای owner فعال است.
مجوز media.upload فقط ایجاد فایل خصوصی است. توقف درخواست از مرورگر لزوماً به معنی عدم دریافت فایل توسط سرور نیست.
صفحه فایل‌های ملکی عمومی (`properties.json`) فعلاً مستقل از پایگاه داده است و باید در فاز یکپارچه‌سازی به منبع واحد منتقل شود.
